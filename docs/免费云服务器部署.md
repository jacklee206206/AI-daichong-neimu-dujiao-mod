# 免费云服务器部署

这套部署让商城、SQLite、上传文件和 Cloudflare Tunnel 在 Linux 云服务器上持续运行，不再依赖个人电脑。GitHub 只保存公开源码与容器镜像；真实数据库、上传内容、运行配置和 Tunnel 凭据只保存在服务器的持久磁盘与私有备份中。

## 1. 架构

```text
GitHub 源码 -> GitHub Actions -> GHCR 多架构镜像
                                      |
用户 -> Cloudflare -> Tunnel -> Nginx 地区网关 -> 商城 -> Redis
                                                    |
                                           SQLite 与 uploads
```

仓库推送到 `main` 后，`publish-image.yml` 会构建 `linux/amd64` 和 `linux/arm64` 镜像并发布到：

```text
ghcr.io/yelinyuan798-commits/ai-daichong-neimu-dujiao-mod:latest
```

首次发布后，在 GitHub 的 Packages 页面把该容器包的可见性设为 Public。否则云服务器需要额外保存 GitHub 读取令牌，既不方便也会增加密钥泄露风险。公开容器只包含本仓库的开源程序，不包含运行数据库、配置或用户数据。

## 2. 云服务器

可使用 Oracle Cloud Always Free 的 Ubuntu 实例。ARM 实例选择 `VM.Standard.A1.Flex`，免费账户总量不要超过账户当前显示的 Always Free 限额。建议把店铺放在账户的持久启动卷，不要使用临时磁盘。

服务器只需要允许 SSH 管理流量。商城端口绑定 `127.0.0.1:8080`，公网访问全部通过 Cloudflare Tunnel，不需要开放 80 或 443。

首次登录服务器后安装 Git、Docker Engine、Compose 插件和 Python 3，然后克隆公开仓库：

```sh
sudo mkdir -p /srv/jacklee-shop
sudo chown "$USER":"$USER" /srv/jacklee-shop
git clone https://github.com/yelinyuan798-commits/AI-daichong-neimu-dujiao-mod.git /srv/jacklee-shop
cd /srv/jacklee-shop
```

## 3. 私有数据迁移

不要把以下内容提交到 GitHub：

- 当前运行使用的 `config.yml`；
- SQLite 数据库及其 WAL 文件；
- `uploads` 中的商品与店铺图片；
- Cloudflare Tunnel 的凭据 JSON；
- 支付、供应商、邮件或 API 密钥。

把现有店铺的完整运行配置复制为服务器上的 `/srv/jacklee-shop/app/config.yml`。把数据库和上传文件分别复制到：

```text
/srv/jacklee-shop/state/db/
/srv/jacklee-shop/state/uploads/
```

迁移 SQLite 前先创建一致性备份，不能只复制一个正在写入的 `.db` 文件而忽略 WAL。正式切换时应暂停旧店铺写入，完成最后一次备份和上传，再启动云端版本。

## 4. 迁移现有 Cloudflare Tunnel

同一个 Cloudflare Tunnel 可以同时运行多个连接器。先复制现有 Tunnel 的凭据，在云端验证成功后再停止 Windows 连接器，可以缩短切换中断。

在服务器创建私有目录：

```sh
cd /srv/jacklee-shop
mkdir -p secrets/cloudflared
chmod 700 secrets secrets/cloudflared
```

将现有 Tunnel 的 UUID 凭据文件复制到 `secrets/cloudflared/UUID.json`。把 `ops/cloudflared.config.yml.example` 复制为 `secrets/cloudflared/config.yml`，将两处占位 UUID 替换为真实 UUID。两个私有文件都设置为 `0600`。

如果 Cloudflare 只配置了根域名，可删除示例中的 `www` 入口；如果根域名和 `www` 都已绑定，则保留两项。

## 5. 启动与验证

确认 GitHub 镜像发布成功后，在服务器执行：

```sh
cd /srv/jacklee-shop
sh scripts/deploy_cloud.sh
curl -fsS http://127.0.0.1:8080/ >/dev/null
```

随后检查：

```sh
docker compose -f compose.cloud.yml ps
docker compose -f compose.cloud.yml logs --tail=100 app cloudflared
curl -I https://jackleeshop.com/
```

只有在商城首页、后台登录、已有订单读取和上传图片都正常后，才停止个人电脑上的旧实例。支付回调应使用支付平台提供的测试机制单独验证。

Compose 中所有服务都使用 `restart: unless-stopped`。服务器重启且 Docker 服务恢复后，商城、Redis、地区网关和 Tunnel 会自动重新运行。

## 6. 备份

`scripts/backup_cloud.py` 使用 SQLite 在线备份 API，不会直接复制正在写入的数据库文件。执行：

```sh
cd /srv/jacklee-shop
python3 scripts/backup_cloud.py
```

生成的压缩包包含数据库、上传文件、运行配置和 Tunnel 凭据，权限为 `0600`。它含有客户数据和密钥，必须再复制到服务器之外的私有存储；不能提交到 GitHub，也不能公开分享。

升级前先备份，然后执行：

```sh
cd /srv/jacklee-shop
git pull --ff-only
sh scripts/deploy_cloud.sh
```
