# 开源范围与来源

本项目记录 Evan 使用 Codex 搭建和改造数字商品商城的过程，并提供整理后的源码。它基于现成开源项目继续开发；“零编程基础完成网站”描述的是提出需求、理解业务、借助工具部署和迭代的经历，不代表从零编写整个商城框架。

## 1. 原项目与版本

最终使用的基础项目是 [Dujiao-Next](https://github.com/dujiao-next/dujiao-next)，基线版本为 `v1.4.8`，原始归档名为 `source-v1.4.8.tar.gz`。代码中 Go module 为 `github.com/dujiao-next`，包含 Go 后端、Vue 客户端和 Vue 管理后台。

前期探索过其他发卡系统，包括 [assimon/dujiaoka](https://github.com/assimon/dujiaoka)。这些选择构成项目的探索过程；本包的最终源码来源是 Dujiao-Next，不能将两者混写成同一套代码。

比较排除了依赖目录、编译产物、测试输出及 Git 数据。逐项路径见 [相对上游的改动清单.tsv](相对上游的改动清单.tsv)。该清单描述**公开包整理前的工作副本差异**，不代表每个文件都是 Evan 独立设计的新功能，也不能据此计算个人原创代码量。原项目本身已经具备大量商城、订单、钱包、上游对接与后台能力。

公开包另外删除运行数据与一次性修复脚本、替换测试中的生产域名及 IP，并调整构建配置。因此，公开包的文件数和内容不再与以上比较结果完全一致。

## 3. 包内包含什么

- `app/cmd`、`app/internal`：服务器入口、业务模块、数据库适配器及测试。
- `app/frontend`：客户商城、管理后台、前端配置、依赖清单和锁文件。
- `app/config.yml.example`：示例配置，使用占位值，供使用者填写自己的环境。
- `app/Dockerfile` 等构建文件：从本包源码构建程序的材料。
- `docs`：个人经历、业务流程、部署说明和代码导读。

读者需要自行配置服务器、域名、支付服务和上游供货连接。源码包不附带可直接使用的生产账号、商户凭据或供货余额。

## 5. 为什么要使用本包自己的构建流程

原项目的 `scripts/dujiao-next-manager.sh` 固定下载官方 `dujiao-next/dujiao-next` release。运行它会安装官方发行版，无法保证包含本包的代理域名接入、供货价和结算等改造。

此外，原 Dockerfile 和 GoReleaser 配置会注入 `BuildType=release`，而后台自更新仍指向官方仓库。改造版如果照此构建并执行官方更新，可能被官方程序覆盖。

本公开包将构建身份设置为 `BuildType=source`，保留源码构建程序的身份。`release,fullstack` 构建标签用于编译行为和嵌入前端，与 `BuildType` 是两个不同设置。需要部署这个改造版时，应按本包的源码构建说明操作。将来若建立自己的发行与升级渠道，应连同下载来源、校验与升级策略一起调整。

## 6. 实际经历与演示数据的边界

项目经历中，可以记录真实完成的部署、已观察到的收款和卡密交付、实际遇到的问题，以及当时的决策过程。某项配置已保存、某段源码存在和某个测试通过，是不同层次的证据，不能替代真实支付与交付结果。

聊天中曾按指定商品数量或随机组合计算收入，并请求修改仪表盘图片。这些计算图不能当作后台真实订单、实际营收或新增用户的证据。本开源包不据此宣称经营业绩；公开经营数字应取自真实订单与财务记录。

退款也需区分：商城记录退款与调整账务、支付平台原路退款、供货商退回采购款，分别涉及不同系统。本包不把人工在支付平台操作退款的经历写成商城已经自动调用了该平台的退款 API。

源码导读说明当前文件的职责，不意味着读者复制后已经具备 Evan 的支付商户、DNS 权限或上游供货资格。每个部署者都需要完成自己的配置。
