# 系统与代码导读

这套系统使用 Dujiao-Next 作为基础商城，再围绕代理独立域名、按订单从上游采购、支付费用提示、代理利润结算和商品 API 供货做改造。以下路径均指本包 `app` 中的源码；职责通过实际文件核对。

## 1. 先理解两种合作方式

**没有网站的代理：**购买域名，由本平台托管店铺。平台按访问域名识别店铺，显示代理设置的售价和图片，统一收款及交付，再将差价记入代理账本。所谓“接入网站 API”在这段经历中主要指域名接入和共享商城能力，不需要代理自行开发 API 客户端。

**已有网站的商家：**保留自己的商城，在自己的服务器配置商品 API 连接。其客户先在其网站付款，商家网站再向本平台下采购单，用商家的采购钱包支付，本平台返回交付结果。这个模式需要对方商城能实现相应协议，单纯绑定域名不会给既有网站增加采购逻辑。

另有一条连接属于 Evan 自己向供货商拿货的**上游采购连接**。方向分别是：

```text
代理域名客户 → Evan 托管商城 → Evan 的供货商 → 卡密交付
已有网站客户 → 商家自己的商城 → Evan 商品 API → Evan 的供货商
```

| --- | --- |

| [reseller/application/domain_saas.go](../app/internal/modules/reseller/application/domain_saas.go) | Cloudflare for SaaS 接入推进，检查 DNS、证书和边缘访问是否可用。 |

DNS 服务商决定一键代写 DNS 是否可用，域名在哪家注册不决定这一点。平台侧 SaaS 授权与代理侧 DNS 授权属于不同权限，不能把某个生产平台令牌放进公开设置或源码。

费用有两层：商城自身的支付费用，以及外部聚合平台在收银台加收的费用。`gateway_customer_fee.go` 中的外部费用是**展示与快照字段**；它不会再次加到商户发起支付的金额，也不直接加入支付回调金额、退款或代理账本，避免重复收费。

商城不加收 USDT 手续费不等于区块链或交易所免手续费。用户应按实际收银台的币种、网络及精确到账数量操作，不能依据商品人民币价格自行估算转账数量。

## 5. 从手工库存到上游自动采购

商品映射将本地商品及规格与上游商品及规格关联起来。收到本地订单后，系统创建采购记录，向上游提交，再通过回调或查询获取交付结果。

| 文件 | 职责 |
| --- | --- |
| [catalog/mapping/application/import.go](../app/internal/modules/catalog/mapping/application/import.go) | 从连接的上游导入商品。 |
| [catalog/mapping/application/sync.go](../app/internal/modules/catalog/mapping/application/sync.go) | 上游映射商品信息及库存等同步。 |
| [procurement/application/create.go](../app/internal/modules/procurement/application/create.go) | 为本地订单建立上游采购记录。 |
| [procurement/application/submit.go](../app/internal/modules/procurement/application/submit.go) | 采购提交、返回结果判断、失败处理及状态未知隔离。 |
| [procurement/application/callback.go](../app/internal/modules/procurement/application/callback.go) | 接收上游状态变化并创建本地交付记录。 |
| [procurement/application/poll.go](../app/internal/modules/procurement/application/poll.go) | 查询上游订单状态，补充回调未及时到达时的同步。 |
| [procurement/application/recovery.go](../app/internal/modules/procurement/application/recovery.go) | 根据数据库状态恢复遗漏的任务；不盲目重下已提交但结果未知的采购。 |
| [internal/upstream/dujiao_next.go](../app/internal/upstream/dujiao_next.go)、[signer.go](../app/internal/upstream/signer.go) | Dujiao-Next 上游协议客户端与签名。 |
| [ProductMappings.vue](../app/frontend/admin/src/views/admin/ProductMappings.vue)、[ProcurementOrders.vue](../app/frontend/admin/src/views/admin/ProcurementOrders.vue) | 后台商品映射及本站向供货商采购的记录。 |

调用上游超时不意味着上游一定没扣款，因此存在“提交结果未知”的状态，需要查询核对，不能简单连续重下。后台 `ProcurementOrders.vue` 主要呈现**本站向供货商采购**，不能拿它替代下游商家的销售统计。

`APISupplyPriceAmount` 为正数时采用固定 API 供货价；为零时保留原有 API 定价逻辑。它与代理独立站供货价是两个字段，修改其中一个不等于修改另一个。自动审批是后台策略，不能据此承诺所有新部署默认开通；停用、拒绝等状态仍有各自规则。

下游订单按 API 凭据所属账号关联并用该账号钱包支付。最近使用时间表示认证调用发生过，查商品或 Ping 也会更新；它不能直接证明已有销售。查看用户订单可以了解其向本站拿货情况，但不能知道其网站其他商品的销量。

| 文件 | 职责 |
| --- | --- |
| [order/application/reseller_pricing.go](../app/internal/modules/order/application/reseller_pricing.go) | 创建订单时保存代理报价及差价相关快照。 |

| [reseller/application/accounting_withdraw.go](../app/internal/modules/reseller/application/accounting_withdraw.go) | 提现申请时锁定利润流水，审核结果更新流水及余额状态。 |
| [reseller/application/accounting_refund.go](../app/internal/modules/reseller/application/accounting_refund.go) | 按退款与订单快照扣减代理利润。 |

| [order/application/refund/wallet.go](../app/internal/modules/order/application/refund/wallet.go) | 退到商城钱包的流程。 |
| [order/application/refund/shared_budget.go](../app/internal/modules/order/application/refund/shared_budget.go) | 父子订单共同退款额度检查，防止重复超额退款。 |
| [dashboard/infrastructure/gormstore/profit.go](../app/internal/modules/dashboard/infrastructure/gormstore/profit.go) | 计算利润概览及退款对利润的调整。 |
| [ResellerWithdraws.vue](../app/frontend/admin/src/views/admin/ResellerWithdraws.vue)、[OrderDetailDialog.vue](../app/frontend/admin/src/views/admin/components/OrderDetailDialog.vue) | 管理员提现审核和订单退款相关界面。 |

92 小时从**实际交付完成**计算，自动确认还要满足订单无异常等资格条件。50 元是 CNY 净可提现余额门槛，不是所有币种折算后的总额，也不是“每次必须提 50 元”的字段。提现会先锁定相应可用流水，完成、拒绝等状态有相应账务处理；管理员仍需真实完成外部打款。

`AdminManualRefund` 明确不调用外部支付渠道，而是登记退款及同步订单账务。支付平台原路退回、供货商采购退款与商城钱包退款分别处理，不能通过一次后台状态修改假定三边资金都已退回。
